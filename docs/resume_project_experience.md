### 项目 1：实时语音转写与流式字幕 / 翻译 / 总结系统（重点）

| 字段 | 内容 |
|------|------|
| **项目归属** | 个人 / 实验室（按实际情况填写） |
| **个人角色** | 后端算法工程师（在已有前端框架上扩展后端全链路） |
| **周期** | 2026.03（持续迭代） |
| **技术栈** | Python · FastAPI · Flask · WebSocket · Faster-Whisper · Silero VAD · ffmpeg · Hunyuan-MT / Ollama（Qwen2.5） |

**项目简介**  
面向真实教学/沟通场景的端到端实时音频处理系统。系统将音频流解码、VAD 语音段切分、ASR 转写、机器翻译与 LLM 流式总结串联为完整链路，通过 WebSocket 向前端实时推送字幕与翻译结果，支持多会话管理与断线重连。在构音障碍辅助场景下，该链路可直接复用：将麦克风采集的发音模糊音频输入同一管线，结合热词与提示词模板大幅提升非标准发音的识别效果。

**工作要点**
- 设计并实现端到端实时音频处理链路：音频流经 ffmpeg 解码重采样 → Silero VAD 语音段检测与切分 → Faster-Whisper ASR 推理 → 翻译 / LLM 总结 → WebSocket 字幕流推送，支持会话状态管理与异常兜底
- 针对 VAD 切片策略进行工程化优化：调整 chunk size、重叠窗口（overlapping）与动态静音阈值，降低构音障碍者短促 / 模糊发音被漏检或截断的概率
- 后端集成领域专属提示词（prompt engineering）：通过自定义词表与上下文模板提升专有词汇（如辅助沟通场景中的高频用语）的识别召回率，可扩展为热词加权解码与个性化词表接口
- 探索流式体验优化方案：对比轻量模型（减少推理延迟）与重型模型（提升准确率）的权衡，记录 VAD 参数与模型选型对端到端延迟的影响，为后续产品迭代提供决策依据
- 架构预留扩展点：会话层支持声纹过滤（Speaker ID 接入）、噪声增益控制与降噪前处理模块的热插拔，适配嘈杂环境下的构音障碍沟通场景

### 项目 2：声纹识别与说话人区分系统（Remote-V2）

| 字段 | 内容 |
|------|------|
| **项目归属** | 个人 / 实验室（按实际情况填写） |
| **个人角色** | 算法工程师（模型集成、推理优化与服务化） |
| **周期** | 2025.12 — 2026.xx（按实际填写） |
| **技术栈** | Python · PyTorch · ERes2NetV2 · Silero VAD · AS-Norm · FastAPI · Flask · CUDA |

**项目简介**  
基于 ERes2NetV2 声纹嵌入模型与 Silero VAD 的说话人验证与区分系统（V14.2）。系统在嘈杂环境下通过 VAD 优先策略（"VAD 为王"）提取有效语音段，再经声纹嵌入与 AS-Norm 自适应归一化评分判断说话人身份。适用于构音障碍辅助沟通中的**声纹过滤**（过滤周围杂音说话人）与**个人声纹注册**场景，是羽言产品中"声纹绑定 + 身份验证"能力的核心算法基础。

**工作要点**
- 构建完整声纹识别链路：Silero VAD 裁剪长静音段 → Kaldi fbank 特征提取（全局 CMVN 归一化） → ERes2NetV2 嵌入推理 → 余弦相似度 + AS-Norm 评分 → 说话人判决，可区分多人混说场景
- 实现批量推理优化（V14.0）：Mini-Batch 切分处理长音频，推理速度相比单段串行提升 **10–50 倍**（数据来源：仓库 README V14.0 版本说明），显存占用约 1.5–2 GB，可与 ASR 服务共卡部署
- 引入 AS-Norm（自适应分数归一化）：利用队列样本对原始余弦相似度进行统计校正，提升跨场景（不同收音设备、不同噪声底噪）的鲁棒性，降低误识与拒识率
- 服务化封装（FastAPI + Web 测试界面）：提供健康检查（Sanity Check）脚本，确保特征前端与模型推理前端完全一致；接口支持音频文件与实时音频流两种输入模式

### 项目 3：ASR 精度提升与模型迁移方案（噪声/方言/热词场景）

| 字段 | 内容 |
|------|------|
| **项目归属** | 个人 / 实验室（按实际情况填写） |
| **个人角色** | 算法研究与方案设计 |
| **周期** | 2026.xx（按实际填写） |
| **技术栈** | Python · Faster-Whisper · Silero VAD · FunASR（Seaco-Paraformer） · FSMN-VAD · DeepFilterNet / BSRNN · LLM RAG（Qwen2.5） |

**项目简介**  
针对嘈杂环境（高噪、多方言、多人混聊）下 ASR 识别率低的问题，系统研究并设计七类精度提升方案，覆盖"前端信号处理 → 中端模型优化 → 后端语义修正"全链路。同时完成从 Faster-Whisper 架构向 FunASR Seaco-Paraformer 的迁移方案设计，显式支持热词加权解码。该研究直接对应构音障碍人群的核心痛点：发音模糊、识别率低、嘈杂环境沟通难。

**工作要点**
- 系统梳理 7 类 ASR 精度提升方案（含方案对比矩阵），按实施难度与收益给出优先级路径：VAD 切片优化 + Prompt 工程为低成本必选；AI 降噪 / 方言路由 / LLM 纠错为进阶选项
- 设计热词加权解码（Seaco-Paraformer Hotword Boosting）：将高频用语与专有词汇构建为热词表，在解码阶段强制提升权重，解决同音字错误（对应构音障碍者"发音接近但字形差异大"的识别失败场景）
- 探索方言专项路由：增加 LID 语种识别模块，标准普通话走 Whisper，方言走 Paraformer-方言版或微调模型，适配构音障碍者伴随的口音/地方发音特征
- 评估模型迁移收益：Seaco-Paraformer（非自回归并行解码）推理速度约为 Faster-Whisper 的 **5–10 倍**（数据来源：仓库 `更换模型方案书.md`），显存需求降低约 80%，支持在同一 GPU 上与声纹识别服务共存部署
- 设计 AB 测试验证计划：准备普通话 / 重口音 / 纯噪音三类测试集，对比 CER（字错误率）与 RTF（实时率），量化热词对专有词汇召回率的提升效果

- VAD 切片优化 + Prompt 工程（低成本必选）：动态阈值防止短促发音被截断，自定义词表提升专有词召回率

- 方言路由 + LLM 语义纠错兜底：LID 模块分流方言模型，LLM + RAG 对 ASR 输出进行上下文修正，全链路覆盖"听不清 / 听不懂 / 写不对"三类错误
