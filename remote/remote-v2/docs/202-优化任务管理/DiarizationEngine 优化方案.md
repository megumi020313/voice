### **V3.1 DiarizationEngine 优化方案：基于多模态证据链的“邻近优先”安全吸附模型**

#### **第一部分：核心解决的问题**

本方案旨在解决 V3.0 “ASR中心化”引擎在处理**说话人切换边界**时遇到的一个核心挑战：**如何精准地为那些恰好落在VAD切分间隙（“三不管”地带）中的词语，找到其正确的说话人归属。**

简单的“最大重叠”或“盲目邻近”算法存在巨大风险，可能导致：
1.  **身份篡改：** 将一个陌生人（如顾客）的短促插话（如“好的”），错误地“吸附”给正在说话的员工，导致顾客的声音被抹除。
2.  **边界漂移：** 将一个说话人发言的结尾词，错误地归属给下一个说话人，导致对话边界不清晰。

本方案通过建立一个**多层次、多模态的证据链决策模型**，来确保“邻近优先”原则只在绝对安全、证据确凿的情况下才被触发。

#### **第二部分：方案核心思想**

**“法庭式审判”：在做出“吸附”判决前，必须通过三道独立且互补的“证据审查”。**

我们不再信任任何单一维度的信息（如距离），而是将每一个落在间隙中的“边界词”都视为一个待审的“案件”。只有当**声学证据 (Z-score)**、**语义证据 (ASR)** 和 **身份证据 (声纹相似度)** 形成一条完整的、无矛盾的证据链时，系统才会做出最终的归属判决。

#### **第三部分：综合仲裁流程 (The Grand Arbitration Process)**

当 `DiarizationEngine` 的 `_find_speaker_for_timestamp` 函数发现一个词语 `X` 落在VAD切分的间隙中时（即与任何SV分段的重叠为0），将**立即启动**以下仲裁流程：

**前提：**
*   `X`: 当前待归属的词语。
*   `A`: `X` 之前的最后一个高置信度说话人片段。
*   `B`: `X` 之后的第一个高置信度说话人片段。

**流程一：【第一把锁】Z-score 静态防御 (声学拒识)**

*   **目的：** 快速排除明显的陌生人或纯噪音，避免无效计算。
*   **操作：**
    1.  提取 `X` 对应音频块的声纹特征 `Embedding(X)`。
    2.  计算 `X` 的独立Z-score：`Z(X)`。
*   **决策：**
    *   **如果 `Z(X) < 1.5` (可配置的硬下限):**
        *   **判决：** `X` 的声学特征与注册库中的**任何人**都存在显著差异，判定为**纯粹的陌生人或噪音**。
        *   **动作：** 将 `X` 的说话人标记为 `unknown`。
        *   **流程结束。**
    *   **否则：**
        *   **判决：** `X` 在声学上具有“可审理性”，进入下一流程。

**流程二：【第二把锁】ASR 语义与置信度保护 (语义不可侵犯)**

*   **目的：** 保护那些虽然短小、但具有独立语义价值的应答或插入语。
*   **操作：**
    1.  获取 `X` 的ASR转写结果 `Word(X)` 及其置信度 `Confidence(X)`。
*   **决策：**
    *   **如果 `Confidence(X) > 0.95` (可配置的高置信度阈值):**
        *   **判决：** `X` 是一个被ASR系统高度确认的、有意义的词语（如“对”、“好的”、“嗯”）。它是一个独立的**语言事件**。
        *   **动作：** 保持 `X` 的独立性，将其说话人标记为 `unknown`（因为它通过了第一道锁，但我们还不知道它是谁）。
        *   **流程结束。**
    *   **否则：**
        *   **判决：** `X` 在语义上是模糊的（可能是无意义的语气词、呼吸声或识别错误的碎片），可以被视为某个说话人发言的延续。进入下一流程。

**流程三：【第三把锁】双向相似度权重 (DNA鉴定)**

*   **目的：** 在确认 `X` 不是明显陌生人且无独立语义后，用最科学的声纹比对来最终确认其“血缘关系”。
*   **操作：**
    1.  获取 `A` 和 `B` 的平均声纹特征 `Embedding(A)` 和 `Embedding(B)`。
    2.  计算 `X` 与前一个说话人 `A` 的余弦相似度：`Sim(X, A)`。
    3.  计算 `X` 与后一个说话人 `B` 的余弦相似度：`Sim(X, B)`。
    4.  计算 `X` 与 `A` 和 `B` 的物理时间距离：`Dist(X, A)` 和 `Dist(X, B)`。

*   **决策 (引入“犹豫区”逻辑):**
    *   **Case 1: 极度邻近 (激进吸附)**
        *   **条件：** `Dist(X, A) < 0.1s` (可配置) 且 `Dist(X, A) < Dist(X, B)`。
        *   **判决：** `X` 极大概率是 `A` 的呼吸、换气或极短的停顿。
        *   **动作：** 将 `X` 的说话人归属为 `Speaker(A)`。
    *   **Case 2: 犹豫区 (条件吸附)**
        *   **条件：** `0.1s <= Dist(X, A) < 0.3s` (可配置)。
        *   **判决：** `X` 存在插话可能，必须进行严格的DNA比对。
        *   **动作：**
            *   **如果 `Sim(X, A) > 0.85` (可配置的硬相似度阈值) 且 `Sim(X, A) > Sim(X, B)`:** 将 `X` 归属为 `Speaker(A)`。
            *   **否则：** 归属失败，将 `X` 标记为 `unknown`。
    *   **Case 3: 距离过远 (禁止吸附)**
        *   **条件：** `Dist(X, A) >= 0.3s`。
        *   **判决：** `X` 与前一个发言的关联性太弱。
        *   **动作：** 将 `X` 标记为 `unknown`。

#### **第四部分：实施建议与配置化**

1.  **函数升级：**
    *   `_find_speaker_for_timestamp` 需要被重构，以支持返回更丰富的状态信息（如 `status: 'gap'`）和距离信息。
    *   需要创建一个新的核心仲裁函数 `_arbitrate_gap_word(word_info, prev_segment, next_segment)` 来实现上述三层流程。

2.  **配置化 (config/model_config.yaml):**
    *   在 `diarization:` 配置段下，增加一个新的子段 `gap_arbitration:`，用于管理所有新引入的阈值。

    ```yaml
    diarization:
      # ... (原有配置) ...
      gap_arbitration:
        # 第一把锁
        min_zscore_for_arbitration: 1.5
        # 第二把锁
        min_asr_confidence_for_independence: 0.95
        # 第三把锁
        proximity_aggressive_ms: 100 # 激进吸附的最大距离
        proximity_hesitation_ms: 300 # 犹豫区的最大距离
        min_similarity_for_hesitation: 0.85 # 犹豫区的硬相似度阈值
    ```
