### 第一部分：深度分析与评价

#### 1. 为什么 V12.0 会出现大量 Silence？
你的 V12.0 采用的是 **“网格投票法 (Grid Voting)”**。
*   **机制**：把时间切成 0.1s 的格子，每个格子独立投票。
*   **缺陷**：
    1.  **VAD 的锅**：如果 Silero VAD 认为某 0.5s 是静音（比如说话停顿），网格直接填 0。
    2.  **分数的锅**：如果某 0.1s 的窗口分数略低于阈值，网格填 0。
    3.  **结果**：原本连续的一句话，被无数个微小的“0”切断了。虽然有平滑逻辑，但如果“0”太多，平滑算法也救不回来，导致大段的 Silence。

#### 2. 豆包参考方案的核心逻辑是什么？
它的核心逻辑是 **“VAD 分段 -> 局部投票 -> 全局合并”**。
*   **不切碎**：它先用 VAD 拿到一个较长的时间段（比如 3秒）。
*   **内部投票**：在这 3秒内，看覆盖了多少个滑动窗口，谁出现的次数多，这 3秒就归谁。
*   **优势**：它利用 VAD 的连续性来保证结果的连续性，而不是靠破碎的网格去拼凑。

#### 3. 可行性评估 (Feasibility)
*   **兼容性**：⭐⭐⭐⭐⭐ (极高)。你已经有了 VAD、滑动窗口、ERes2Net。这套方案只是改变了**“怎么组合这些积木”**的逻辑。
*   **解决痛点**：⭐⭐⭐⭐⭐ (极高)。它专门解决“说话人时间戳对齐”和“碎片化”问题，正是你现在的死穴。
*   **改造成本**：⭐⭐⭐ (中等)。需要重写 `inference_pipeline.py` 的核心循环逻辑，废弃 `calculate_diarization_intervals` 的网格逻辑。

#### 4. 对参考文档的评价
*   **优点**：
    *   **逻辑分层清晰**：物理层（VAD）定边界，逻辑层（声纹）定身份。这是工业界标准做法。
    *   **CMVN 自适应**：这是一个亮点。通过统计说话人的均值方差来校准特征，能有效解决“忽大忽小、忽远忽近”导致的分数波动。
*   **缺点/风险**：
    *   **聚类 (Clustering)**：文档提到了 AHC 聚类。对于你的“火锅店”场景（已知注册人 + 未知顾客），**不需要复杂的聚类**。直接用“最大相似度匹配”即可，聚类反而会引入延迟和不确定性。

### 第二部分：针对“Silence 异常”的紧急修正方案 (V13.0)

我们不完全照搬豆包的聚类，而是**吸取其“VAD 容器 + 多数投票”的精华**，来替换掉你现在的“网格法”。

**核心思想**：
1.  **VAD 为王**：VAD 说这段是人声，它就是人声（绝不显示 Silence）。
2.  **窗口投票**：在这段 VAD 人声里，包含的 10 个窗口，如果有 6 个说是 zlh，那这段就是 zlh。
3.  **强力缝合**：如果两段语音间隔很短，且都是 zlh，直接缝合。

#### 2. 重写 `src/pipeline/inference_pipeline.py` (核心改造)

**废弃**之前的 `calculate_diarization_intervals` 网格逻辑。
**采用** “VAD 引导 + 窗口投票” 逻辑。

```python
    def run(self, audio_numpy):
        # 1. 获取 VAD 时间戳 (粗粒度分段)
        # 假设返回 [{'start': 0.5, 'end': 3.5}, {'start': 4.0, 'end': 8.0}]
        vad_segments = self.vad_model.get_speech_timestamps(audio_numpy)
        
        if not vad_segments:
            return { ... "segments": [] ... }

        # 2. 生成滑动窗口 (细粒度特征)
        # windows = list of (start, end, embedding)
        windows_data = self._extract_windows_and_embeddings(audio_numpy)
        
        final_results = []
        
        # 3. 【核心】VAD 容器 + 多数投票
        for vad_seg in vad_segments:
            vad_start = vad_seg['start']
            vad_end = vad_seg['end']
            
            # 找到落在该 VAD 片段内的所有窗口
            relevant_windows = []
            for w in windows_data:
                # 窗口中心点在 VAD 片段内
                w_center = (w['start'] + w['end']) / 2
                if vad_start <= w_center <= vad_end:
                    relevant_windows.append(w)
            
            if not relevant_windows:
                continue
                
            # 投票：这段 VAD 到底是谁？
            # 统计每个用户的累积得分或出现次数
            user_scores = {}
            
            for w in relevant_windows:
                # 计算该窗口与所有注册用户的相似度
                best_u, best_s = self._identify_window(w['embedding'])
                
                # 只有超过阈值才计票
                if best_s > self.config.low_threshold:
                    if best_u not in user_scores: user_scores[best_u] = []
                    user_scores[best_u].append(best_s)
            
            # 决断
            if not user_scores:
                # 没有人匹配上 -> 陌生人/顾客
                segment_user = "unknown" # 或者 "customer"
                segment_score = 0.0
            else:
                # 选得分最高的那个用户
                # 或者选出现次数最多的 (豆包思路)
                # 这里建议：取平均分最高的用户
                best_candidate = max(user_scores.items(), key=lambda x: sum(x[1])/len(x[1]))
                segment_user = best_candidate[0]
                segment_score = sum(best_candidate[1]) / len(best_candidate[1])
            
            # 生成片段
            final_results.append({
                "start": vad_start,
                "end": vad_end,
                "user": segment_user,
                "score": segment_score
            })

        # 4. 后处理：合并相邻的同类片段
        merged_results = self._merge_segments(final_results)
        
        return { ... "segments": merged_results ... }
```

    def _merge_segments(self, segments):
        if not segments: return []
        merged = [segments[0]]
        for curr in segments[1:]:
            prev = merged[-1]
            
            # 如果是同一个人
            if prev['user'] == curr['user']:
                gap = curr['start'] - prev['end']
                # 允许 1.0s 内的缝隙合并
                if gap < 1.0:
                    prev['end'] = curr['end']
                    # 更新分数 (加权平均)
                    prev_dur = prev['end'] - prev['start']
                    curr_dur = curr['end'] - curr['start']
                    prev['score'] = (prev['score']*prev_dur + curr['score']*curr_dur) / (prev_dur + curr_dur)
                    continue
            
            merged.append(curr)
        return merged

### 第三部分：为什么这个方案能解决 Silence 问题？

1.  **逻辑反转**：
    *   **旧方案 (V12)**：先切碎成 0.1s，再试图拼起来。如果中间碎得太厉害，就拼不起来，变成 Silence。
    *   **新方案 (V13)**：先由 VAD 圈定一个 **“肯定有人说话”** 的大范围（比如 3秒）。在这个范围内，**强制**选出一个身份。
    *   **结果**：只要 VAD 不断，中间绝对不会出现 Silence。

2.  **VAD 参数调整**：
    *   将 `min_silence_duration_ms` 设为 `500ms`。这意味着说话时的停顿（通常 200-300ms）**不会**导致 VAD 切断。VAD 输出的本身就是一段连续的语音。
