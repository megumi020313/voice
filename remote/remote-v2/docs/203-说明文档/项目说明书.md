# 声纹识别产品逻辑架构说明书

## 第一部分：产品全景概述

### 1.1 产品定义
代码实现了完整的声纹识别系统，同时支持 1:1 声纹核验和 1:N 声纹辨识功能。系统采用端到端的推理流水线，能够从音频输入中提取声纹特征，并与已注册的声纹模板进行比对或检索，实现说话人身份的验证和识别。同时集成了 ASR 语音识别能力，为多模态融合分析提供基础。

**当前版本**：V15.0（2025-12-25）
- **V14.1**：工程事故修复（时间戳异常和识别逻辑错误修复）
- **V15.0 (最新)**：代码目录重构 (`src` -> `backend`)，集成 **Whisper ASR**，打通 **IoTDB 数据层**，实施 **V2.0 声纹质量优化**（智能会话融合）。

### 1.2 核心技术模型

#### 1.2.1 声纹识别模型：ERes2NetV2
- **模型架构**：基于 ERes2NetV2 深度神经网络
- **特征维度**：192维声纹特征向量
- **核心能力**：
  - **批量推理**：支持 Batch 输入，10-50x 性能提升
  - **AS-Norm 归一化**：通过自适应 S 归一化计算高可靠性 Z-score
- **模型路径**：`models/eres2netv2/pretrained_eres2netv2.ckpt`
- **核心代码**：`backend/models/speaker/eres2netv2.py`

#### 1.2.2 语音活动检测模型：Silero VAD
- **模型类型**：Silero VAD（Voice Activity Detection）
- **关键参数**（V2.0 优化）：
  - `vad_threshold`: 0.3（检测阈值）
  - `min_speech_duration_ms`: 250ms（最小语音时长）
  - `min_silence_duration_ms`: **800ms**（允许自然停顿，减少碎片化）
  - `speech_pad_ms`: 30ms（语音片段前后填充）
- **模型路径**：`models/vad/`
- **核心代码**：`backend/models/vad/silero_vad.py`

#### 1.2.3 听觉识别模型：Faster-Whisper
- **模型架构**：Whisper-Large-v3
- **核心功能**：语音转文本 (ASR)，支持多语言识别
- **优化细节**：
  - **简体中文引导**：使用 `initial_prompt` 引导模型直接输出简体中文
  - **性能平衡**：使用 `beam_size=5` 平衡速度与精度
- **核心代码**：`backend/modules/audio_analysis/whisper_svc.py`

#### 1.2.4 核心优化算法：智能会话融合 (V2.0 核心)
- **逻辑**：将被 VAD 错误切分的同源片段，通过“时间(1.5s) + 声纹相似度(0.80)”双重校验进行缝合。
- **安全校验**：超过 10s 的合并执行拼接点声纹一致性检查，防止说话人泄漏 (Speaker Leakage)。
- **核心代码**：`backend/pipeline/inference_pipeline.py` 中的 `_intelligent_merge_segments` 方法

## 第二部分：运行逻辑与业务流程

### 2.1 声纹注册与模板管理

#### 2.1.1 注册流程概述
声纹注册是系统建立身份基准的核心流程：
1.  **多样本增强注册**：为提高模板鲁棒性，系统支持多样本注册（默认建议 3 个）。对每个注册样本，系统会根据配置决定是否同时提取"原始纯净音频"和"加噪增强音频"的声纹特征，最终通过向量加权平均生成该用户的唯一声纹模板。
2.  **注册质量控制 (Quality Gate)**：注册音频必须通过 VAD 检查和 SNR 质量检测。若样本中有效语音时长不足 5s 或有效片段少于 3 个，系统将拒绝注册，确保底库质量。
3.  **模板持久化**：生成的 192 维特征向量连同用户元数据（注册时间、样本数等）存储于 Vector DB（本地 Pickle 或 Redis）。

#### 2.1.2 详细实现流程

**配置控制**：
- 加噪增强功能由配置文件 `config/model_config.yaml` 中的 `registration.noise_augmentation.enabled` 控制
- 如果 `enabled: true`，系统会对每个音频片段提取两次特征（原始 + 加噪），然后平均
- 如果 `enabled: false`，系统只提取原始音频特征，跳过加噪增强步骤

**阶段1：音频预处理与切分**
1. 接收用户上传的音频数据（支持单样本或多样本）
2. 对每个音频样本进行 VAD 检测，切分出有效语音片段
3. 过滤掉时长 < 0.5s 的片段（太短无法提取有效特征）

**阶段2：质量检测与过滤**
1. 对每个语音片段计算 SNR（信噪比）
2. 拒绝 SNR < 5dB 的片段（噪音过大）
3. 记录每个片段的时长、SNR 等质量指标

**阶段3：特征提取（核心）**

根据配置选择不同的特征提取策略：

**策略A：加噪增强模式（`noise_augmentation.enabled: true`）**
```
对于每个有效语音片段：
  1. 提取原始音频的声纹特征 → embedding_clean (192维)
  2. 使用 augment_with_noise() 生成加噪版本
     - 噪音因子范围：noise_ratio_min ~ noise_ratio_max (默认 0.1~0.3)
     - 噪音源：data/noise/background.wav
  3. 提取加噪音频的声纹特征 → embedding_augmented (192维)
  4. 对两个特征向量求平均 → embedding_final
     embedding_final = (embedding_clean + embedding_augmented) / 2
```

**策略B：纯净模式（`noise_augmentation.enabled: false`）**
```
对于每个有效语音片段：
  1. 提取原始音频的声纹特征 → embedding_final (192维)
  2. 跳过加噪增强步骤
```

**阶段4：阶梯式决策逻辑**

系统根据有效片段数量和总时长采用三级决策：

| 级别 | 条件 | 策略 | 说明 |
|------|------|------|------|
| **第3级（警告态）** | 有效片段 < 3 或总时长 < 5s | **拒绝注册** | 质量不达标，无法生成可靠模板 |
| **第2级（标准态）** | 有效片段 3-10 个 | **全部使用** | 数据保全策略，避免浪费有效样本 |
| **第1级（理想态）** | 有效片段 > 10 个 | **随机采样8个** | 防止过拟合，保证模板泛化能力 |

**阶段5：加权平均聚合**

对选定的 N 个特征向量进行加权平均：
1. 计算初步质心：`centroid_init = mean(embeddings)`
2. 计算每个向量到质心的余弦距离：`distance_i = 1 - cosine_similarity(embedding_i, centroid_init)`
3. 使用高斯函数计算权重：`weight_i = exp(-gamma * distance_i^2)`
4. 执行加权平均：`final_template = weighted_average(embeddings, weights)`
5. L2 归一化：`final_template = final_template / ||final_template||`

**阶段6：存储与返回**
1. 将最终模板存入 Vector DB
2. 记录元数据：
   - 有效片段数量
   - 选定片段数量
   - 总时长
   - 是否使用加噪增强
   - 注册时间
3. 返回注册成功结果

**配置示例**：
```yaml
# config/model_config.yaml
registration:
  num_samples: 3  # 建议注册样本数
  noise_augmentation:
    enabled: true  # 是否启用加噪增强
    noise_ratio_min: 0.1  # 最小噪音混合比例
    noise_ratio_max: 0.3  # 最大噪音混合比例
```

### 2.2 听觉感知与预处理逻辑
系统接收音频流后，首先进入**动态感知阶段**：
1.  **VAD 智能切分**：Silero VAD 模型实时检测音频中的人声。通过设置 `min_silence_duration_ms=800`，系统可以容忍对话中自然的呼吸和思考停顿，避免将一个连续的句子切碎。
2.  **智能会话融合 (Merge)**：这是提升识别质量的关键。系统会计算相邻语音片段的时间间隔和声纹相似度。
    - 如果间隔 `< 1.5s` 且声纹余弦相似度 `> 0.80`，系统认为这属于同一说话人的连续表达，将其“缝合”为长片段。
    - **安全校验机制**：若合并后的时长超过 10 秒，系统会在拼接点执行二次声纹抽样检查，确保没有发生说话人切换（防止 Speaker Leakage）。

### 2.3 语音转文本 (ASR) 处理
在确定有效的语音片段后，系统并行触发 **ASR 推理**：
1.  **简体中文引导**：利用 Whisper 模型的 `initial_prompt` 功能，强制模型使用简体中文编码，无需繁简转换后处理。
2.  **时间轴对齐**：每个 ASR 识别结果都绑定了精确的绝对 UTC 时间戳（毫秒级），确保听觉文字信息可以与视觉、传感器等其他模态数据在时序上完美对齐。

### 2.4 声纹特征工程与识别
声纹识别采用**高分辨率滑动窗口**方案：
1.  **Batch 批量推理**：系统将语音片段切分为多个 1.0s 的滑动窗口，打包成 Batch 送入 GPU。这种方式比传统逐个识别提速 10-50 倍。
2.  **AS-Norm 评分体系**：系统不是直接使用原始余弦相似度，而是通过 **Adaptive S-Normalization**。它使用 500 个背景样本（Cohort）作为参照系，计算 Z-score。
    - **Z-score 意义**：它代表了当前识别结果偏离背景噪声的程度。Z-score 越高，识别的可信度呈指数级增长。

### 2.5 多维数据持久化
识别结果会根据用途流向不同的存储引擎：
1.  **Vector DB**：存储用户的 192 维声纹模板，用于身份检索。
2.  **IoTDB (时序数据库)**：存储“事件级”数据。路径格式为 `root.store_01.audio.{device_id}`，记录说话人 ID、文字内容及时间戳，支撑多模态融合查询。

## 第三部分：系统边界与性能契约

### 3.1 输入约束 (Input Constraints)
为保证识别质量，输入音频必须满足以下硬性要求：
- **格式**：16kHz 采样率，单声道，16-bit PCM。
- **质量**：信噪比 (SNR) 建议 `> 5dB`。
- **时长**：单次有效语音建议 `> 1.5s` 以保证声纹特征的饱满度。

### 3.2 识别性能指标
| 指标项 | 预期表现 | 说明 |
| :--- | :--- | :--- |
| **Z-score 分数区间** | 11.0 ~ 14.0 | 经过 V2.0 优化后的典型高置信度区间 |
| **推理延迟 (ASR)** | ~0.5s / 3s 音频 | V100 GPU 加速下的处理速度 |
| **并发能力** | 10+ 路实时流 | 依赖 Batch 推理优化后的吞吐量 |
| **误识率 (FAR)** | < 0.1% | 在 Z-score > 5.5 时的理论表现 |

### 3.3 关键逻辑阈值 (Thresholds)
系统决策依赖以下核心参数，可在 `model_config.yaml` 中配置：
- **`high_threshold` (5.5)**：严格判定阈值。Z-score 超过此值时，系统极高概率确认身份。
- **`low_threshold` (2.9)**：准入判定阈值。低于此值将被标记为 "unknown" 或拒绝。
- **`similarity_threshold` (0.80)**：融合相似度。控制智能合并的激进程度。

### 3.4 异常处理与降级
- **静音处理**：若 VAD 未检测到语音，系统直接返回空结果，不触发后续昂贵的 GPU 推理。
- **库路径兼容**：启动脚本 `start_api.sh` 具备自愈能力，会自动检测并加载 `nvidia` 相关动态库，解决 `cuDNN` 加载失败导致的崩溃。
- **IoTDB 模拟模式**：当 IoTDB 服务不可达时，连接器自动切入模拟模式（Mock Mode），仅打印日志而不影响声纹识别主业务。
