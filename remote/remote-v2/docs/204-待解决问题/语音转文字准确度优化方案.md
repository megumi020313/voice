# 语音转文字准确度优化方案

## 现状与问题

- **技术栈**：Faster-Whisper Large-v3（`whisper_svc.py` + `model_config.yaml`）
- **主要问题**：识别准确度低；文档已记录的 ASR 幻觉（超长词、零时长词、重复短语）会进一步拉低可用准确度

---

## 一、优化层次总览

| 层次 | 方案 | 优先级 | 预期效果 |
|------|------|--------|----------|
| 1 | 音频质量与预处理 | 高 | 从源头提升信噪比与格式规范 |
| 2 | ASR 模型参数调优 | 高 | 提升解码质量、减轻幻觉 |
| 3 | ASR 幻觉后处理 | 高 | 过滤异常词，立即改善观感 |
| 4 | 长音频分段策略 | 中 | 减少长段带来的漂移与错误 |
| 5 | 模型/引擎升级 | 低 | 长期根本提升 |

---

## 二、方案 1：音频质量与预处理

**目标**：保证输入满足「16kHz、单声道、足够信噪比」，减少因格式或噪声导致的错误。

- **采样率/声道**：入口统一重采样到 16kHz、转单声道（若当前未做，在送入 Whisper 前处理）。
- **降噪（可选）**：对明显嘈杂的音频，在 pipeline 前端增加轻量降噪（如 noisereduce、webrtc-vad 等），避免过度损伤语音。
- **文档约定**：在《音频转文字技术实现说明书》中明确「建议信噪比 > 10dB、标准普通话、单段 < 10 分钟」，便于业务侧收数规范。

**实施**：在 `backend/pipeline` 或调用 `WhisperService` 前增加一段音频预处理（重采样 + 单声道 + 可选降噪），并写进配置开关（如 `asr.preprocess.normalize_sample_rate`）。

---

## 三、方案 2：ASR 模型参数调优

**目标**：在现有 Faster-Whisper 上提高准确率并降低幻觉，无需换模型。

### 3.1 推荐配置调整（`config/model_config.yaml`）

```yaml
asr:
  enabled: true
  language: zh
  initial_prompt: "以下是普通话的句子。"   # 保持，利于简体中文
  beam_size: 10                          # 5→10，优先准确率时可再提高
  compute_type: float16                  # GPU 时用 float16，CPU 保持 float32
  vad_filter: true                       # 建议开启，过滤静音区噪音词
  # 以下为新增/扩展参数（需在 whisper_svc 中透传）
  condition_on_previous_text: false      # 出现重复/幻觉时设为 false
  temperature: 0.0                       # 贪婪解码，稳定输出
  no_speech_threshold: 0.5               # 可微调，降低则对弱语音更敏感
  log_prob_threshold: -1.0               # 同上
```

### 3.2 参数说明与代码改动

- **beam_size**：当前为 5，提高到 10 可提升准确率，速度会变慢；若需实时可保留 5 或折中 8。
- **vad_filter**：建议 `true`，用 Whisper 内置 VAD 过滤静音区，减少静音段误识别。
- **condition_on_previous_text**：若日志中出现「重复短语、跨段重复」等幻觉，在 `whisper_svc.py` 的 `transcribe` / `transcribe_with_word_timestamps` 中传入 `condition_on_previous_text=False`（并从 config 读取）。
- **temperature**：设为 0 使用贪婪解码，输出更稳定，利于准确率。

**实施**：在 `backend/modules/audio_analysis/whisper_svc.py` 中，从 `get_config()` 读取上述新项，并在 `self.model.transcribe(..., **kwargs)` 中传入；若当前 faster-whisper 版本不支持某参数，可先忽略并逐步加上。

## 四、方案 3：ASR 幻觉后处理（推荐优先实现）

**目标**：在 VAD 过滤之后（或与 VAD 过滤并列）对词级结果做合理性检查，剔除明显幻觉词。

**思路**：在 `backend/pipeline/inference_pipeline.py` 的 `recognize_parallel_v3` 中，在取得 `asr_results` 后、`_filter_asr_by_vad` 之前或之后，增加一步「幻觉过滤」：

1. **超长词**：单词时长 > 阈值（如 3s）则丢弃。
2. **零时长词**：`end <= start` 或时长 ≈ 0 则丢弃。
3. **过短词**：时长 < 最小阈值（如 0.05s）可丢弃（可选，按业务决定）。
4. **连续重复词**：同一词连续出现 ≥ N 次（如 3 次）则视为幻觉，丢弃多余部分。

**配置建议**（可放在 `model_config.yaml` 的 `asr` 下）：

```yaml
asr:
  hallucination_filter:
    enabled: true
    max_word_duration: 3.0    # 秒
    min_word_duration: 0.05  # 秒（可选）
    max_repeat_count: 3      # 连续重复次数阈值
```

**实现要点**：参考《V3.1架构局限性分析-ASR幻觉问题》中的「方案 G」伪代码，实现 `_filter_asr_hallucinations(asr_words)`，在 pipeline 中：

```text
asr_results = self.asr_service.transcribe_with_word_timestamps(...)
asr_results = self._filter_asr_hallucinations(asr_results)  # 先幻觉过滤
asr_results = self._filter_asr_by_vad(asr_results, optimized_segments)
```

这样可先去掉明显不合理词，再按 VAD 做边界过滤，避免幻觉词影响后续对齐与展示。

## 五、方案 4：长音频分段策略

**目标**：长音频一次性识别容易产生漂移、重复和超长词幻觉，分段可缓解。

- **做法**：对超过一定时长（如 60s 或 120s）的音频，按静音或固定时长（如 30s）切段，逐段调用 `transcribe_with_word_timestamps`，再按时间戳合并词列表（注意首段可不使用 `condition_on_previous_text`，避免跨段重复）。
- **注意**：分段会带来边界处可能的截断或重复，需要在合并时做简单去重或边界微调（例如相邻段首尾词若相同则合并或去一）。

**实施**：在 pipeline 层根据 `audio_duration` 或 VAD 段长度决定是否分段，再循环调用 ASR 并合并结果；可配置 `asr.max_segment_duration_sec` 与 `asr.merge_overlap_threshold_ms`。

## 六、方案 5：模型/引擎升级（长期）

- **继续使用 Faster-Whisper**：跟进 Large-v3 的后续版本与最佳实践（如 temperature、condition_on_previous_text 的推荐组合）。
- **评估其他引擎**：若幻觉或领域词错误仍突出，可评估 WeNet、FunASR、Paraformer 等中文 ASR，做 WER/幻觉率对比后再考虑替换或双引擎投票（见《V3.1架构局限性分析-ASR幻觉问题》方案 I/J）。

---

## 七、推荐实施顺序

1. **立即**：方案 3（幻觉后处理）  
   - 实现 `_filter_asr_hallucinations` 并接入 pipeline，配置化阈值。  
   - 预期：明显减少超长词、零时长词、重复短语对准确度观感的影响。

2. **短期**：方案 2（参数调优）  
   - 在 `model_config.yaml` 与 `whisper_svc.py` 中落实 `beam_size=10`、`vad_filter=true`、`condition_on_previous_text=false`、`temperature=0.0` 等，并在测试集上对比准确率与幻觉率。

3. **短期**：方案 1（音频预处理）  
   - 统一 16kHz/单声道，可选降噪与配置开关，保证所有请求都符合《音频转文字技术实现说明书》中的输入要求。

4. **按需**：方案 4（长音频分段）  
   - 若长音频（如 >2 分钟）错误率明显高于短音频，再上分段与合并逻辑。

5. **长期**：方案 5  
   - 持续跟踪 Faster-Whisper 更新，必要时做多模型对比或集成。

---

## 八、效果验证建议

- **准确率**：用一批带人工标注的测试音频计算字/词错误率（CER/WER）或正确率。
- **幻觉率**：统计过滤前后「超长词、零时长词、连续重复」的数量与占比。
- **业务指标**：按「首段置信度」「说话人归属正确率」等现有指标看是否同步改善（首段问题可继续依赖现有首段锚点修正与 warm-up 等逻辑）。
