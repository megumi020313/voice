# 规则文件结构说明

本文档说明 `.cursor/rules/` 目录下所有规则文件的类型和应用方式。

## 规则类型分类

根据 [Cursor 规则文档](https://docs.cursor.com/zh/context/rules#%E8%A7%84%E5%88%99%E7%BB%93%E6%9E%84)，规则文件分为以下类型：

### Always（始终包含）- 3个

这些规则始终包含在模型上下文中，是强制性核心开发流程和导航索引：

1. **ep.mdc** (140行) - 主索引文件，规则导航和项目概览
2. **任务管理与功能点完成流程.mdc** (267行) - 任务创建、变更日志、功能点完成流程
3. **需求分析流程.mdc** (286行) - 从灵感到需求分析的完整流程，包括原子性拆分

### Apply to Specific Files（文件匹配）- 4个

当编辑匹配类型的文件时自动触发的专业规范：

1. **导入路径规范.mdc** (48行) - Python文件路径导入
2. **魔法数字规范.mdc** (77行) - 代码文件常量定义
3. **终端环境与编码处理.mdc** (123行) - Python脚本环境
4. **文档管理规范.mdc** (411行) - Markdown文档格式

### Apply Intelligently（智能触发）- 14个

根据上下文和文件类型智能触发的专业规范：

1. **ep.mdc** (288行) - 主索引文件，包含核心原则、模块定位规则、依赖规则
2. **YesDev集成规范.mdc** (308行) - YesDev MCP服务集成，需求管理、任务管理、问题跟踪
3. **文档管理规范.mdc** (411行) - 本地文档管理规范，需求、任务、Bug、优化等文档的组织结构
4. **函数规范.mdc** (156行) - 函数设计、抽象和复用规范
5. **模块划分规范.mdc** (430行) - 详细的模块定位和依赖关系规范

### Auto Attached（自动附加）- 1个

当引用匹配某个 glob 模式的文件时自动包含：

1. **终端环境与编码处理.mdc** (123行)
   - **globs**: `["**/*.py", "scripts/**"]`
   - **说明**: 当处理 Python 脚本时自动包含

### Agent Requested（AI 请求）- 11个

对 AI 可用，由其自行决定是否包含。每个规则都有清晰的描述，说明何时使用：

1. **导入路径规范.mdc** (49行)
   - **描述**: Python 导入路径规范，绝对路径 vs 相对路径。当编写Python代码并需要导入模块时使用。

2. **数据与配置规范.mdc** (约250行)
   - **描述**: 前后端数据层和配置管理规范，数据模型、类型定义同步和配置管理。处理数据模型、类型定义或配置时使用。

3. **日志规范.mdc** (约200行)
   - **描述**: 前后端日志管理、异常处理规范，统一日志标准和异常处理机制。处理日志或异常处理代码时使用。

4. **需求分析流程.mdc** (286行)
   - **描述**: 从灵感到需求分析的完整流程，包括需求拆分和优先级评估。进行需求分析时使用。

5. **文档管理规范.mdc** (411行)
   - **描述**: 本地文档管理规范，需求、任务、Bug、优化等文档的组织结构和维护流程。创建或更新文档时使用。

6. **YesDev集成规范.mdc** (308行)
   - **描述**: YesDev MCP服务集成规范，需求管理、任务管理、问题跟踪的自动化流程。使用 YesDev 相关功能时使用。

7. **任务管理与功能点完成流程.mdc** (244行)
   - **描述**: 任务创建、变更日志、功能点完成流程，包括文档和版本管理。完成任务或创建变更日志时使用。

8. **Git提交规范.mdc** (371行)
   - **描述**: Git 提交信息格式、版本号管理、Windows 环境编码处理、约定式提交规范。进行 Git 提交时使用。

9. **提示词模板.mdc** (126行)
   - **描述**: AI 助手使用的提示词模板和快速参考，包括模块选择、依赖检查、导入路径。AI 需要快速参考时使用。

10. **工具与测试文件夹规范.mdc** (约120行)
    - **描述**: tools/ 和 tests/ 目录规范、工具分类规则。处理工具或测试代码时使用。

11. **Notion集成规范.mdc** (516行)
    - **描述**: Notion MCP服务集成规范，页面创建、内容更新、页面移动等操作的正确使用方法。使用 Notion 相关功能时使用。

## 规则使用建议

### 对于开发者

1. **强制流程**（Always 规则）：始终强制执行核心开发流程
   - 任何开发工作前自动建立需求文档
   - 强制原子性拆分需求，建立对应任务
   - 完成后自动更新文档和CHANGELOG
2. **专业规范**（Apply Intelligently）：AI根据上下文智能加载相关规则
3. **特定文件**（Auto Attached）：处理匹配文件类型时自动包含

### 对于 AI 助手

1. **Always 规则**：始终强制执行核心开发流程
   - **任务管理与功能点完成流程**：任何开发工作完成后必须执行
   - **需求分析流程**：任何需求必须原子性拆分

2. **Apply Intelligently 规则**：根据开发上下文智能判断
   - 编写Python导入 → 自动加载"导入路径规范"
   - 处理数据模型 → 自动加载"数据与配置规范"
   - 处理日志代码 → 自动加载"日志规范"
   - 创建/更新文档 → 自动加载"文档管理规范"
   - 使用YesDev功能 → 自动加载"YesDev集成规范"
   - 编写函数代码 → 自动加载"函数规范"
   - 处理模块架构 → 自动加载"模块划分规范"
   - Git提交代码 → 自动加载"Git提交规范"
   - 使用Notion工具 → 自动加载"Notion集成规范"
   - 处理工具/测试 → 自动加载"工具与测试文件夹规范"

3. **Auto Attached 规则**：文件匹配时自动包含
   - 处理Python脚本 → 自动包含终端环境规范

## 📋 函数索引维护规范

### 强制要求
**所有函数开发必须同步维护函数索引**：

#### 📁 索引存储结构
```
docs/design/index/
├── 函数索引总览.md          # 主入口索引
├── core_函数索引.md         # 核心业务函数
├── backend_函数索引.md      # 后端模块函数
├── frontend_函数索引.md     # 前端组件函数
└── utils_函数索引.md        # 工具函数

docs/design/modules/
├── approval_函数索引.md     # 审批模块
├── finance_函数索引.md      # 财务模块
├── procurement_函数索引.md  # 采购模块
├── asset_函数索引.md        # 资产模块
└── integration_函数索引.md  # 集成模块

docs/design/services/
├── user_service_函数索引.md        # 用户服务
├── procurement_service_函数索引.md # 采购服务
├── finance_service_函数索引.md     # 财务服务
└── asset_service_函数索引.md       # 资产服务
```

#### 📝 索引内容要求
每个函数条目必须包含：
- ✅ **完整签名**: `function_name(param: type) -> return_type`
- ✅ **文件位置**: 准确路径和行号
- ✅ **功能描述**: 详细功能说明
- ✅ **参数说明**: 每个参数的作用
- ✅ **返回值说明**: 返回值类型和含义
- ✅ **使用示例**: 实际调用代码
- ✅ **依赖关系**: 依赖和被依赖关系

#### 🔄 更新时机
- **新增函数**: 立即创建索引条目
- **修改函数**: 更新签名和说明
- **删除函数**: 移除对应索引条目
- **重构函数**: 更新所有相关信息

### AI助手使用指南

#### 🎯 查询优先级
1. **主索引**: `docs/design/index/函数索引总览.md` - 快速定位模块
2. **模块索引**: 根据功能选择具体模块索引文件
3. **详细查找**: 通过函数名或功能描述定位具体函数

#### ⚡ 开发加速
- **避免重复**: 开发前先检查索引是否存在相似功能
- **快速上手**: 通过示例代码直接了解函数用法
- **依赖理解**: 通过依赖关系了解函数调用链

## 🏗️ 开发流程规则触发机制

### 阶段化触发策略

#### 🎯 需求分析阶段
**触发**: 需求分析流程 (Always)
**执行**: 需求原子性拆分 → 建立需求文档 → YesDev需求创建
**规则**: 强制执行，确保任何开发任务都有明确需求定义

#### 📝 任务规划阶段
**触发**: 任务管理与功能点完成流程 (Always)
**执行**: 任务创建 → 模块函数定义 → YesDev任务同步
**规则**: 强制执行，确保每个原子需求都有对应任务

#### 🔧 代码开发阶段
**触发**: 文件类型匹配 + 上下文智能
**执行**:
- **文件编辑时**: 自动触发相应规范 (导入路径、魔法数字、函数设计等)
- **架构设计时**: 触发模块划分规范
- **数据操作时**: 触发数据配置规范
- **日志处理时**: 触发日志规范
- **YesDev操作时**: 触发YesDev集成规范

#### 🧪 测试阶段
**触发**: 工具与测试文件夹规范 (Apply Intelligently)
**执行**: 测试代码组织 → 测试工具使用规范
**规则**: 编写测试代码时自动触发

#### ✅ 交付阶段
**触发**: 任务管理与功能点完成流程 (Always)
**执行**: YesDev状态更新 → 文档更新 → CHANGELOG创建 → Git提交规范触发
**规则**: 强制执行，确保完整交付流程

### 触发优先级

1. **Always规则**: 最高优先级，始终强制执行
2. **文件匹配规则**: 当编辑匹配文件时自动触发
3. **智能规则**: 根据开发上下文判断是否触发
4. **手动规则**: 需要明确引用时触发

### 流程固化效果

- **标准化**: 每个开发阶段都有标准规则触发
- **自动化**: AI助手自动加载相关规范
- **完整性**: 确保开发流程的每个环节都有规范指导
- **效率化**: 减少手动规则查找，提升开发效率
